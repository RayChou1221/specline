# 空项目安全门

本文定义 `/specline-init-web` 的确定性准入规则。安全门的目标不是判断“看起来可以合并”，而是证明目标是**可安全初始化的空项目**。

## 1. 不变量

- 第一次扫描必须发生在任何询问、命令初始化、依赖解析或写入之前。
- 第二次扫描必须发生在用户选择完成、精确输出清单形成之后，第一次目标快照仍保留用于比较。
- 两次扫描前都不得修改目标；第二次扫描通过之前，目标中的写入数量必须为零。
- 任一检查无法完成、结果不确定或目标发生变化时 fail closed。
- 没有 force、覆盖、合并、移动、删除或自动清理路径。

## 2. 允许内容

只允许以下类别；路径必须是正常目录/普通文件，不能是 symlink：

1. Git 元数据：
   - `.git/`（目录内容视为 Git 内部元数据，但 `.git` 为文件或 symlink 时阻断）；
   - 根级 `.gitignore`；
   - 根级 `.gitattributes`。
2. 受支持 Agent 平台配置：根级 `.cursor/`、`.claude/`、`.codex/`、`.opencode/` 及其普通文件/目录内容。
3. Specline 运行文件：
   - 根级 `specline/` 及其普通文件/目录内容；
   - 根级 `AGENTS.md`，仅当它属于已安装的 Specline 运行文件；
   - 位于上述受支持 Agent 平台目录中的 Specline 部署文件。

“属于 Specline”必须能由已安装 manifest、已知 canonical 路径或明确的 Specline 标识证明；不能仅凭文件名猜测。平台配置目录内若存在明显应用代码、secret、symlink 或无法读取项，仍阻断。

除 allowlist 外全部阻断，包括但不限于：`README*`、`LICENSE*`、`.env*`（含 `.env.example`）、`package.json`、`go.mod`、源码、构建产物、任意未知隐藏文件。

## 3. 扫描算法

对目标做不跟随 symlink 的递归只读遍历，并记录：

- 候选目标的规范化绝对路径、存在状态与文件类型；
- 候选不存在时，最近既存祖先的解析后绝对路径及其到候选之间每个路径分量的不存在状态；
- 每个条目的相对路径、类型、size、mtime（可用时也记录 inode/device）；
- symlink 的存在本身，不读取其目标；
- 无法读取、遍历或分类的条目。

要求：

1. 候选已存在时必须为真实目录；候选不存在时，其最近既存祖先必须为真实可遍历目录，且候选路径各分量不得经过 symlink。已存在非目录、祖先关键路径解析异常或无法完整读取均阻断。
2. 已存在候选目录递归扫描全部内容；不存在候选则递归扫描最近既存祖先，但仅对候选路径状态和可能影响候选创建的同名项做快照，不把祖先中的其他项目内容误判为候选内容。
3. 遍历不得跟随 symlink；allowlist 内出现 symlink 也阻断。
4. 将候选内每项与 allowlist 分类；未知项进入阻断列表。
5. 第一次扫描生成排序后的规范快照，保留到第二次扫描完成。
6. 第二次扫描用相同算法生成快照，逐项比较候选路径、候选内容及相关祖先分量的路径、类型和记录元数据；新增、删除、类型变化或元数据变化均视为竞态并阻断。

不要依赖普通 glob：它可能遗漏 dotfiles。不要仅依赖 `git status`：未跟踪忽略项和 Git 外内容可能不可见。

## 4. 精确输出清单检查

第二次扫描还必须验证：

- 清单中的每个最终输出路径都不存在；
- 从目标到输出文件的每个关键父路径均不是 symlink；
- 计划创建的根级目录不会与 allowlist 目录混用；
- 脚手架可能隐式生成的文件（lockfile、缓存、环境文件）已纳入清单，否则不得运行；
- 安装命令不会修改既有 Specline、Git 或 Agent 平台文件。

若输出清单与现状有任何冲突，报告冲突路径并停止。

## 5. create-exclusive 语义

- 候选目标不存在时，目标目录本身也必须原子 exclusive 创建；目标已存在时不得再次创建或改写根目录。后续目录仅允许“原路径不存在则创建”；遇到 `EEXIST` 必须停止，不把它当作成功。
- 创建文件必须使用原子 exclusive create（等价于 POSIX `open(..., O_CREAT|O_EXCL)`）；禁止 `> file`、普通 `writeFile`、覆盖式 copy。
- 重命名/复制进目标时也必须保证目标不存在；不能用覆盖语义。
- Vite 等生成器只能在目标外的隔离临时目录运行；审核完整输出后逐项 exclusive copy。临时目录不得位于目标目录内。初始化失败后也不得自动清理该临时目录；将其位置和状态列入报告，由用户决定。
- 包管理器或构建工具若可能改写 `package.json`、lockfile、dist、cache 等已存在路径，不得直接运行；应在隔离临时工作树安装和验证，再把精确清单中的最终项目文件逐项 exclusive materialize 到目标。依赖缓存和 `node_modules` 不属于交付清单，不复制到目标。
- 每次成功创建后记录相对路径；失败报告必须区分目录和文件。

## 6. 阻断报告格式

扫描阶段阻断时输出：

```text
初始化已阻断：目标不是可安全初始化的空项目。
阻断项：
- <relative-path> — <原因：不在 allowlist / symlink / 无法读取 / 两次扫描变化 / 输出冲突>
本次零写入。未执行覆盖、合并、移动、删除或清理。
```

如第一次扫描已通过但第二次阻断，仍须写“本次零写入”。生成开始后的失败不得再声称零写入，应改为列出完整已创建项。
